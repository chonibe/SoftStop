How Governor Decides "Appropriate"

Governor doesn't "know" in a human sense. It enforces explicit, observable rules — no ML, no intent inference.

The ONLY question Governor asks:
"Has this user already received enough pressure of this type within the defined limits?"

✅ Allowed Signals

Explicit, observable, binary facts.

  • Pressure events — urgency shown, discount applied, modal displayed
  • User resistance — dismissed popup, ignored CTA, unsubscribed
  • Time — last escalation, cooldown expiry, session window
  • Surface metadata — checkout page, email channel, pricing view
  • Hard policy — max 1 discount/30d, caps per session

🚫 Banned Signals

These turn Governor into an optimizer.

  • Funnel stage — awareness, consideration, conversion labels
  • Intent scores — high intent, conversion likelihood, propensity
  • Personalization — personas, demographics, cohort, LTV
  • AI reasoning — confidence scores, agent justifications
  • Business goals — revenue targets, conversion KPIs
If interpretation is required, it's banned.

Decision Logic (Deterministic)

1. Identify escalation type
2. Fetch user pressure state
3. Apply rules in order:
a. Hard block?
b. Cooldown active?
c. Cap exceeded?
4. Return ALLOWED / BLOCKED + reason
// Example result
allowed: false
reason: "urgency_cap_reached"
retry_after: "7d"

❌ What Governor Does NOT Do

"User is highly engaged, so a discount would help them convert."
This is optimization logic. Not Governor's job.

✅ What Governor DOES Do

"A discount was already shown 3 days ago. Policy allows max 1 per 14 days. Block."
Pure enforcement. No interpretation.
Signal boundary litmus test:
"Would two engineers always interpret this signal the same way?"
Yes → Allowed
No → Banned
